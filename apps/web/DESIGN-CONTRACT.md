> 이 문서는 홈페이지를 손대는 모든 작업자(사람·에이전트)가 지켜야 하는 **강제 규격**이다.
> 근거 문서: `D:\전광판\teams\blog\research\web-benchmark-2026.md` (Apple/Toss/Linear/Stripe 실측 스펙)

## 0. 절대 규칙 (어기면 반려)

1. **임의 값 금지.** `text-[42px]`, `py-[88px]`, `duration-[420ms]`, `rounded-[18px]` 같은 즉흥 수치를 새로 적지 않는다. 아래 토큰만 쓴다.
2. **이징은 4종.** `ease-entrance` / `ease-state` / `ease-scrub` / `ease-spring`. 새 cubic-bezier를 컴포넌트에 적지 않는다.
3. **이미지 경로 하드코딩 금지.** 반드시 `@/lib/imageAssets` 의 `IMAGES` 를 통해 참조한다.
4. **모션 부품은 `@/components/motion` 에서 가져온다.** `motion.div` 에 직접 transition을 적지 않는다. (부품에 없는 연출이 필요하면 그 파일에 부품을 추가하고 쓴다.)
5. **`prefers-reduced-motion` 경로가 없는 애니메이션은 금지.** motion 부품은 이미 처리돼 있다.
6. **애니메이션은 transform / opacity / filter 만.** `top`, `height`, `margin` 을 애니메이션하지 않는다.
7. **검증 불가능한 숫자·고객 로고·"만족도 99%" 금지.** 우리는 아직 첫 수주 전이다. 실적을 지어내지 않는다.
8. **끝내기 전 `npx tsc --noEmit` 통과.** (빌드는 총괄이 마지막에 한 번 돌린다.)

### 진입 모션의 위계 (2026-09-07 신설 — 이게 없어서 홈이 평평했다)

같은 등장을 모든 곳에 쓰면 아무것도 중요해 보이지 않는다. 세 단으로 나눈다.

| 세기 | 부품 | 쓰는 자리 |
|---|---|---|
| 강 | `SplitText` | 히어로 H1, 페이지 대표 섹션 제목. **페이지당 2회** |
| 중 | `RiseMask` | 그 밖의 섹션 제목. **섹션당 1회** |
| 약 | `Reveal` | eyebrow(`y=10`) · 리드(`y=14`, `delay 0.16`) · 본문 |

섹션 머리는 **eyebrow → 제목 → 리드** 순으로 0.06 / 0.16 씩 밀어 넣는다. 이 순서를 바꾸지 않는다.

🔴 `RiseMask` 를 움직이는 부모(`Reveal`) 안에 넣지 않는다. 두 움직임이 겹쳐 어느 쪽도 읽히지 않는다.
   제목은 `Reveal` 밖으로 꺼내고 형제로 둔다. (`CtaSection` 이 그 예다.)

**2026-09-07 v6 추가분 — 왜 상한을 더 두지 않았나**
`GrowBar` 는 한 차트 안에서 6~15개가 동시에 자란다. 얼핏 예산 초과로 보이지만
**하나의 그림이 한 번 그려지는 것**이지 서로 다른 연출이 여섯 개 도는 것이 아니다.
개수를 묶는 대신 차트 단위로 묶는다 — 한 섹션에 자라는 차트를 셋 이상 두지 마라.
`LedSwap` 은 사용자가 눌러야만 도는 상태 전환이라 스크롤 예산과 성격이 다르지만,
한 페이지에 둘 이상이면 "탭을 누를 때마다 화면이 번쩍이는 사이트"가 된다.

**왜 상한을 올렸나** — 예산은 성능과 산만함을 막으려고 둔 것이다. 그런데 실제로 벌어진 일은
반대였다. `SplitText` 2회를 히어로와 `ProductShowcase` 가 쓰고 나니 **나머지 섹션 제목 네 개는
아무 등장도 갖지 못했고**, 그래서 섹션 사이에 위계가 생기지 않았다. 예산이 "화려함"이 아니라
"밋밋함"을 만들고 있었다. 그래서 강한 부품(`SplitText`)의 상한은 그대로 두고, **싸고 조용한 중간
단계(`RiseMask`)를 새로 만들어 그 자리를 채웠다.** `RiseMask` 는 motion 요소가 하나뿐이라
어절 수만큼 요소를 만드는 `SplitText` 와 비용이 다르다.

`once: false` 상한 2 의 이유 — 되돌아갈 때 다시 움직이는 요소는 강하다. 셋 이상이면 스크롤을
되감을 때 화면 전체가 들썩인다. 현재 사용처는 `ProcessTimeline` 의 마디 하나뿐이다.

## 5. 반드시 피할 것 (안티패턴)

1. 첫 화면 자동 슬라이더 4~6장 → 히어로 한 장 + 사용자가 여는 갤러리
2. "최고의 기술력, 최상의 품질" → `6,000 nit`, `IP65`, `KC 적합등록` 같은 검증 가능한 속성
3. 무지개 그라디언트·네온 남발 → 중립 90% / blue 8% / 상태색 2%
4. 모든 카드에 두꺼운 그림자 + 30px radius
5. 접속 즉시 팝업·채팅·전화 버튼 3개 → 첫 CTA 하나, 40% 스크롤 뒤 sticky 바
6. 제목마다 다른 폰트·900 굵기
7. 스크롤할 때 모든 요소가 아래에서 튀어나옴 → 주요 장면만 24~40px, 목록은 opacity 중심
8. 모든 문장 가운데 정렬 → 중앙 정렬은 히어로 2~3줄에만
9. 제품 메뉴를 모델명만으로 구성 → "실내 고해상도 P1.8–P2.5"처럼 환경·성과를 먼저
10. PDF 아이콘만 있고 크기·날짜 없음 → `규격서 · PDF · 2.4MB · 2026-08 개정`

## 6. 이미지

- `IMAGES` 레지스트리(`src/lib/imageAssets.ts`)에 60장이 **중복 없이** 배정돼 있다. 배정을 바꾸려면 레지스트리를 고치고 중복 검사를 통과시킨다.
- 히어로 이미지 1장만 `priority`, 나머지는 lazy. `sizes` 를 반드시 정확히 준다 (격자면 `(min-width:1024px) 33vw, (min-width:640px) 50vw, 100vw`).
- 생성 이미지의 매끈함이 거슬리는 큰 장면에는 `.wk-grain` 을 얹는다.
- `alt` 는 "장소 + 제품 + 상황". 장식용이면 `alt=""` + `aria-hidden`.

### 🔴 사진이 없는 자리는 **코드로 그린다** (2026-09-07 신설 — v6)

205장 가운데 근거 자리(Ⓑ)에 쓸 수 있는 실사는 2장뿐이다(구조정본 §17-E).
그러니 "이미지를 더 넣어라" 의 답은 **AI 연출컷을 더 배선하는 것이 아니라 코드 비주얼**이다.
전송량 0 · 진위 문제 0 이고, 도해는 사진보다 정확할 때가 많다.

| 수단 | 선례 |
|---|---|
| SVG 도해 | `/services` `MountDiagram` — 취부 3방식, 사진 0장 |
| `PitchDots` (화소 간격 도해) | `/products` SpecScale · `/industries` 비교표 (2026-09-07 신설) |
| `GrowBar` 데이터 막대 | `/products` SpecScale 시청거리·밝기 두 축 |
| `.wk-pixelgrid` / `.wk-emit` 계열 | 다크 면의 재료 표현 |

🔴 **도해는 배율을 속이지 않는다.** 한 묶음 안에서는 반드시 같은 배율을 쓰고,
   실제 크기가 아니라는 것과 배율값을 화면에 적는다. 축척이 다른 사진을 도해 옆에 둘 때는
   "축척이 다르다"를 캡션에 명시한다.

## 7. 접근성

- 본문 대비 5:1 이상을 내부 목표로 한다. `wk-ink4`(#8B95A1)는 흰 배경에서 3.04:1이라 18px 미만 설명문에 쓰지 않는다.
- 모든 인터랙티브 요소에 포커스 링(globals.css에 전역 지정됨). 제거하지 않는다.
- 색만으로 상태를 전달하지 않는다. 선택 탭 = 색 + 2px 밑줄 + 굵기.
- 200% 확대에서 내비게이션·CTA·규격표가 잘리지 않아야 한다.

## 8. 카피 톤

- 독자는 **관공서·학교 담당 공무원**이다. 결재 문서에 붙일 근거를 찾고 있다.
- 과장·영어 남발 금지. "혁신적 솔루션" 대신 "부서가 바뀌면 화면에서 고칩니다".
- 문장은 짧게. 한 문단 3줄 이내.
